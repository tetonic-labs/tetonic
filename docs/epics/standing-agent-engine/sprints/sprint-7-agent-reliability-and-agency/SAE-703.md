# SAE-703: Propagate generation options and provider stop reasons

Status: Planned
Owner: Tetonic Engine (lokai repository)
Priority: P0
Milestone: M1
Estimate: 5 relative points (planning estimate, not a delivery commitment)
Dependencies: None

## Outcome and implementation

Audit BrainRequest through every used inference adapter. Forward output limits through provider-specific options, preserve temperature and supported structured-output configuration, and preserve actual stop/length/error reasons. The current SingleModelBrain path does not forward the requested max_tokens value.

Trace effective generation options after provider mapping. Distinguish unsupported options from silently ignored ones. Do not treat an output limit as a substitute for input budgeting.

## Acceptance criteria

- [ ] A fake provider receives the exact configured completion limit from BrainRequest.
- [ ] Provider length exhaustion is represented as truncation rather than a normal stop.
- [ ] Captured diagnostics show effective context and output limits without exposing secrets.
- [ ] Supported provider mappings have tests; unsupported combinations return an actionable configuration error or documented capability response.

## Validation

Unit tests for request mapping and response finish reasons, plus one local provider integration smoke test.

## Delivery notes

Keep changes local. Record implementation files, commands/results, migration behavior and remaining limitations here when completed. Do not mark complete from a successful model utterance alone. Resolve dependency ticket IDs through the sprint indexes in each repository.
