# SAE-701: Versioned perception, action and lifecycle contract

Status: In progress
Owner: Tetonic Engine (lokai repository)
Priority: P0
Milestone: M1
Estimate: 5 relative points (planning estimate, not a delivery commitment)
Dependencies: None

## Outcome and implementation

Define a world-neutral, versioned contract for observations, available capabilities, durable event IDs, agent/session identity, world epoch, observation sequence, task IDs and action correlation. Separate state snapshots from events that require delivery acknowledgement. Document compatibility negotiation and migration from the current envelope. Keep game-specific object properties in adapter data.

Publish JSON fixtures and schema validation for perception, action acknowledgement, task completion/failure/cancellation, and runtime health. Define acknowledgement as accepted for processing versus actually incorporated into a decision; do not conflate either with belief or compliance.

## Acceptance criteria

- [ ] Both repositories validate identical contract fixtures, with explicit failure on unsupported major versions.
- [ ] A movement acknowledgement cannot be mistaken for arrival; every completion can be correlated to its originating action.
- [ ] Two agents and two world sessions cannot collide in event or decision identity.
- [ ] Old clients receive an explicit compatibility response rather than silently losing fields.

## Validation

Contract tests with a synthetic, non-game adapter and the Village gateway. Cover reordered, duplicated, missing optional, and unknown-version envelopes.

## Delivery notes

Keep changes local. Record implementation files, commands/results, migration behavior and remaining limitations here when completed. Do not mark complete from a successful model utterance alone. Resolve dependency ticket IDs through the sprint indexes in each repository.
