# SAE-705: Agent health and decision lifecycle telemetry

Status: In progress
Owner: Tetonic Engine (lokai repository)
Priority: P0
Milestone: M1
Estimate: 5 relative points (planning estimate, not a delivery commitment)
Dependencies: SAE-701, SAE-704

## Outcome and implementation

Publish separate lifecycle states for observing, queued, inferring, validating, acting, waiting, recovering, failed and stopped. Include timestamps, decision ID, last successful decision, error classification and retry count. Physical activity remains adapter-owned.

Provide a bounded snapshot/event API suitable for the Village HUD and other clients. Detect stale inference/connection health using configured deadlines. Expose measured processing progress without claiming access to hidden model reasoning.

## Acceptance criteria

- [ ] A failed inference cannot be reported solely as healthy idle.
- [ ] A connected transport with repeatedly failing decisions is visibly unhealthy.
- [ ] Reconnect obtains current health without reconstructing it from an unbounded trace.
- [ ] Lifecycle events correlate to request, output, validation and action stages.

## Validation

State-machine tests and a local integration test with forced provider outage followed by recovery.

## Implementation checkpoint — 2026-09-24

Added payload-free current decision health to the engine health endpoint, independent of trace capture enablement. States cover inferring, validating, action_pending, acting, waiting, action_rejected and failed, with classification, last success and retained failure metadata. Village displays this independently from connection/physical status. Tests cover disabled trace and failure-to-success transitions. Remaining: explicit queued/recovering/stopped states, stale deadline classification, full lifecycle contract and multi-agent snapshots.
