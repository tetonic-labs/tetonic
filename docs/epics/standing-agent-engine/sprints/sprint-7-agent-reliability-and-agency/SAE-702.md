# SAE-702: Context budgeting and selective request assembly

Status: In progress
Owner: Tetonic Engine (lokai repository)
Priority: P0
Milestone: M1
Estimate: 8 relative points (planning estimate, not a delivery commitment)
Dependencies: SAE-701

## Outcome and implementation

Introduce a configurable total context budget with reserved completion capacity and a safety margin. Budget system instructions, current state, events, retrieved memories and tools before inference. Use model/provider token counting where available; document conservative fallback estimation. Keep the full memory store independent of what is retrieved.

Prioritize safety/control state, current actionable observations and undelivered events. Trim or summarize optional history with provenance. If essential input cannot fit, emit a context-budget error instead of silently dropping required state or sending a predictably invalid request. Expose section sizes and omissions in diagnostics.

## Acceptance criteria

- [ ] Configured input budget plus completion reserve and safety margin never exceeds the configured context limit under the selected accounting method.
- [ ] A growing history and dense observation fixture complete at least 100 decisions without prompt growth exceeding the budget.
- [ ] Budgeting preserves E-stop, identity, current task, current objective revision and pending critical events.
- [ ] Oversized essential input fails visibly and does not produce an action.

## Validation

Deterministic tests at and around the budget boundary; replay the supplied trace shapes at 4096 tokens. Use sanitized/minimized fixtures committed to tests, not a dependency on the user's Downloads file.

## Delivery notes

Keep changes local. Record implementation files, commands/results, migration behavior and remaining limitations here when completed. Do not mark complete from a successful model utterance alone. Resolve dependency ticket IDs through the sprint indexes in each repository.


## Implementation checkpoint — 2026-09-24

Added context_budget.rs and configurable completion_tokens (384 default), context_margin (512 default). Assembly preserves current observations/events and removes optional older memories/intents until within the estimated allowance. Essential overflow emits a classified error without calling inference. Diagnostics disclose estimated accounting and omissions. UTF-8 bytes/3 plus chat overhead is a conservative heuristic for this workload, not a tokenizer guarantee; exact model accounting and richer retrieval remain pending.

Validation: 100 growing-history assembly iterations and boundary/Unicode/essential-overflow tests; fake-provider test confirms overflow makes no inference call. Live initial decisions reported 1786-2127 input tokens under the 4096 context with complete stop responses. No 30-minute soak claimed.
