# SAE-708: Event-aware scheduling and acknowledged delivery

Status: In progress
Owner: Tetonic Engine (lokai repository)
Priority: P1
Milestone: M2
Estimate: 8 relative points (planning estimate, not a delivery commitment)
Dependencies: SAE-701, SAE-705

## Outcome and implementation

Separate high-frequency snapshots from reliable stimuli/outcomes. Coalesce replaceable state while retaining bounded unacknowledged events. Define delivery acknowledgement after durable retention or documented processing, not merely after generating a perception.

Wake decisions for significant events, arrival, operator steering and wait deadlines. Support configurable idle backoff and minimum/maximum cadence. Serialize decisions per agent and define interruption/stale-output handling.

## Acceptance criteria

- [ ] A one-tick message during inference is retained for a subsequent decision.
- [ ] Walking does not require repetitive idle model calls solely to wait for arrival.
- [ ] New stimuli wake a waiting resident within the configured scheduling bound.
- [ ] Duplicate delivery is deduplicated and queue overflow is explicit; no silent event loss.

## Validation

Virtual-clock tests for coalescing, long inference, arrival, backoff, interruption and queue limits.

## Agent-continuity checkpoint — 2026-09-24

Implemented the retained-event delivery subset with protocol-1 acknowledgement callback after valid parsing. Failed, truncated or oversized decisions do not acknowledge pending events. A bounded transport queue sends acknowledgements independently of physical actions; failed enqueue leaves world events available for retry. New unseen retained events bypass the normal decision cadence. Voluntary idle uses configurable agent.idle_interval_ms (default 30000, never below normal cadence); inference errors return to normal cadence. wait_scheduled trace distinguishes a voluntary wait from a failure.

Tests cover delivery over a real WebSocket, failed decision followed by successful inclusion, repeated snapshots and early wake on a new event without repeated wake for the same ID. Remaining: durable acknowledgement, configurable event priorities, interruptible inference, explicit deadlines and broader scheduler/backpressure policy.
