# SAE-712: Trace completeness and reproducible reliability harness

Status: Planned
Owner: Tetonic Engine (lokai repository)
Priority: P0
Milestone: M1
Estimate: 5 relative points (planning estimate, not a delivery commitment)
Dependencies: SAE-701, SAE-705

## Outcome and implementation

Distinguish export-window completeness from complete per-decision coverage. The supplied export begins mid-output despite incomplete:false; make missing request/prefix stages explicit. Include capture boundaries, truncation, source cursors, schema versions and effective configuration metadata.

Build deterministic fake-provider regression scenarios from the observed failure classes. Keep raw-model evidence separate from inferred causes. Preserve redaction and bounded storage.

## Acceptance criteria

- [ ] A trace beginning mid-decision identifies that decision as partial even if no transport gap occurred.
- [ ] Exports support joining engine actions, world receipts and asynchronous outcomes unambiguously.
- [ ] The harness reproduces context exhaustion, malformed output, stale action rejection and provider outage.
- [ ] No test relies on exact stochastic model prose or requires disclosure of hidden reasoning.

## Validation

Trace buffer wrap, reconnect, export-window and redaction tests; document one reproducible local command for the harness.

## Delivery notes

Keep changes local. Record implementation files, commands/results, migration behavior and remaining limitations here when completed. Do not mark complete from a successful model utterance alone. Resolve dependency ticket IDs through the sprint indexes in each repository.
