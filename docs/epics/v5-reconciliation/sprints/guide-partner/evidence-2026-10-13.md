## Ownership and contracts

- `engine/strata/tetonic-context/src/conversation.rs` owns reusable evidence
  selection and byte-bounded packing. It has no product intent classifier.
- `engine/strata/tetonic-memory/src/control/guide_context.rs` owns subject/focus
  revisions and source authorization. Schema 77 introduces these records without
  duplicating transcripts or changing execution ownership.
- `engine/strata/tetonic-memory/src/control/guide_attention.rs` owns incident
  identity, assessment admission, read state and settings. Schema 78 adds durable
  receipts and observation freshness. Unknown or interrupted usage is not refunded.
- `engine/litho/tetonic-app/src/work/director/` composes existing work, resource,
  history and runtime services. The host's 15-second reconciliation loop observes
  facts; it is not a second worker scheduler. No browser needs to stay open.
- `web/src/components/team-work/GuideContext.tsx`, `GuideUpdates.tsx` and
  `GuideAttentionSettings.tsx` extend the current Guide, Needs you and workspace
  settings. The map and navigation structure are preserved.

The [local API contract](../../../../implementation/contracts/local-ui-v1.md)
and [durable-state ownership](../../../../architecture/durable-state-and-contracts.md)
describe the current invariants, ceilings and recovery semantics.

## Live qualification

An isolated profile, `.lokai/guide-partner-ce1ff190`, uses the saved OpenAI vault
reference and the model returned by discovery, `gpt-6.1-sol`. Credentials are not
copied into evidence or committed. The owner's existing profiles were not seeded
or reset. Temporary worker files live outside engine/control storage.

The Guide and two saved agents use the existing general harness. Workers have
only `read_file`, `write_file` and `list_dir` in their approved temporary folder.
The test author supplied two source files and natural-language intent; the model
created and revised the plan. No hand-authored plan was substituted for its output.

The journey was:

1. Explain the effect of a 20% increase followed by a 20% decrease. The Guide
   answered 96 and 4% below the original without setup or a proposal.
2. Explore a lightweight reading afternoon for 12 adults, two hours and a $180
   ceiling. Correct the participation rule to forbid mandatory introductions or
   speaking; discuss an unrelated balcony-gardening idea; return to the event.
3. Save the relevant understanding with source references. A new conversation
   recovered `LIB-47Q`, the correction and the distinction between tentative
   suggestions and settled boundaries. A real engine restart retained the notes
   and conversation before delegation.
4. Request independent programme and cost/logistics documents from the two saved
   partners, then revise timing in the composer: reading ends at 15:45 and the
   final 15 minutes are quiet cleanup. The UI showed version 2 as the sole current
   proposal, with version 1 under history.
5. Start through the existing UI. Polling recorded both workers in `running` at
   the same time. While they worked, a separate gardening question received a
   direct answer without interrupting or altering the event effort.
6. Both agents read the source files and saved `programme-draft.md` and
   `supplies-logistics-draft.md`. The coordinator combined their findings. Actual
   files were inspected: the schedule totals 120 minutes, preserves quiet cleanup
   and optional participation; priced modules cite the CSV and distinguish known
   subtotals from unknown taxes, fees and supplies.

## Failures found and repaired

- The expanded default Guide purpose exceeded the agent editor's 4,000-byte
  contract. It was shortened to 3,902 bytes and given a regression test. Hosted
  configuration now saves through the unchanged editor contract.
- The hanging-model test server blocked discovery for every connection. It now
  holds only the inference socket, so the foreground-preemption regression tests
  the actual engine behavior instead of a broken discovery fixture.
- A provider stream failed after the revised proposal was saved. The existing
  receipt preserved revision 2. A subsequent Guide reply inspected that version
  and confirmed the correction without recreating it. The UI now explicitly
  explains this saved-proposal/interrupted-reply case. The unconfirmed provider
  call retains 12,809 held tokens rather than reporting a refund.
- The first result question submitted three managed host inspections in one
  batch. That boundary rejects batches, and recovery exhausted the test Guide's
  24,576-token allowance before an answer. The capability now states its actual
  one-call-per-response contract and points to the overview/targeted evidence
  choices. This does not serialize independent workers or add intent routing.
- Result attention initially used a shared plan run sequence. Sibling progress
  therefore invalidated an unchanged child's assessment. Incident signatures now
  hash that work's actual state, result, human requests and error. A regression
  verifies that unrelated sequence changes do not create a new assessment, while
  changed result evidence does.

## Scope and limits

Automatic attention is deliberately read-only: it can inspect and explain but
cannot write discussion notes, propose, dispatch, grant, stop or resume work.
This is a stricter ceiling than the planning document's optional derived-note/
proposal path. Foreground conversation retains its existing governed proposal
capabilities. Current signals cover human requests, recorded blockers, recorded
tool failures, the 80% reported-token threshold and results; they do not monitor
arbitrary external services or infer failures from slowness.

Assessment admission is at most one outstanding per owner/team, with at most
256 pending candidates considered and a finite daily token reserve. The UI
returns up to 100 incident records and initially shows five. Each check reserves
its full configured allowance, including interrupted/unknown calls. An identical
resolved/reappearing incident is shown conservatively without automatic replay.
Restart reconciles uncertain assessments instead of silently starting them again.

Subject and original-message lookup remain bounded and scope-checked. Lexical
selection is not semantic or perfect recall; the model must retrieve omitted
evidence. Saved understanding is revisable and may need human correction. No
background summarization model or embeddings store was introduced.

This engineering walkthrough is not the owner's usability signoff. It also does
not close the separate 5–10-agent / 10–30-task useful-width proof, production
distributed deployment, packaging or October release readiness gates.
