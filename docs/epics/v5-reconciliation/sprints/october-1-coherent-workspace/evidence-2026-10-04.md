## Implemented changes in the working tree

- Agent creation treats omitted or empty tool selections as no file tools. Unknown or host-disallowed tools are rejected, duplicates are removed, and the catalog exposes host-supported tools. Hosted file grants remain rejected pending an authorized disclosure path.
- Connected setup offers the host's supported harness/tools. Hosted setup requires prompt/history consent and offers no unsupported workspace tools. The CLI and development launcher no longer grant the current repository implicitly; file access requires an explicit workspace argument.
- Durable work stores the full original input separately from its short display title. Same-ID retries compare the entire request, including content beyond the title prefix. Restored conversation context uses that stored input. Existing ResourceService authorization, work storage and managed execution remain the authorities.
- The context provider creates UUID work identifiers and stops scheduling polls after unmount. Broader retry ownership and endpoint-failure handling remain open.
- Approval decisions await one parent-owned mutation, block duplicate clicks, and retain failures without displaying a receipt. The main App checks the returned approval identity, proposal digest and status. A digest-only approval is displayed as an unavailable effect and cannot be approved.
- Fixed frontend build errors. Extracted local workroom methods from the oversized local workspace module without adding another store or dispatcher; the architecture gate passes.
